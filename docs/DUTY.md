# 值守规则（写死在仓里，防止上下文丢失后失效）

## 1. 价格时段

| 时段（CST, UTC+8） | 姿态 |
|---|---|
| **00:30 – 08:30** | 可迭代：派单、写代码、提交、发版 |
| **08:30 – 00:30** | **休眠**：不派单、不改代码、不提交、不创建新目标 |

判断方式（每次开工前跑一次）：

```powershell
(Get-Date).ToString("yyyy-MM-dd HH:mm:ss")
```

## 2. 休眠到底怎么做

"休眠"不是把进程挂着，而是**不再产生自动续轮**，因为那才是最贵的部分：

1. **不创建新 goal**——goal 会自动唤醒并整段重放上下文，峰值期这是纯烧钱。
2. 峰值期内每一轮**只用零工具调用收尾**（一句"休眠中"），不做任何检查性轮询。
3. 有在跑的任务时，先让它跑完并记录状态，再进入休眠；不要把未完成的派单留在峰值期无人验收。
4. 恢复条件：下一次用户消息，或时段回到 00:30–08:30。

## 3. 不可逾越的红线（与时段无关）

- 不删除/归档仓库、不 force push、不重写已推送历史
- 未经确认不向第三方仓库提 PR/issue、不发帖、不注册付费服务、不写密钥
- 团队被部署限制为 8 人，只能复用现有 teammate

## 4. 每次开工的检查顺序

1. `Get-Date` → 现在是不是 00:30–08:30？
2. `git pull` → 有没有别人的提交进来、CI 是不是红的？
3. 有 red CI 先修 red，再谈新功能。
4. 派单必须带五要素：目标 / 边界 / 约束 / 验收标准 / 需要回报的证据。

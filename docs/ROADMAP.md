# ROADMAP

> 主线：**让 agent 的行为像代码一样可测、可 diff、可回归。**
> 版本规则：每个版本必须能独立演示，且必须带来一个**可复现的数字**；没有数字的版本不发。

## 已完成

| 版本 | 主题 | 数字 |
|---|---|---|
| v0.1 | 能跑：cassette + 确定性 replay + 断言 + diff | 39 测试，CI 绿 |
| **v0.2** | 能用：可安装、统计断言、日志导入、pytest 插件、cassette 规范 + 第三方独立实现、BOM 容忍 | 153 测试，CI 绿 |

## v0.3 —— 多次运行的回归看板（进行中）

- `agenttest regress`：一批 run 的断言结果汇总成 Report
- 基线比对：`newly_failing` / `fixed` / 通过率与成本 delta，每个新失败标出第几个事件
- 单文件 HTML 报告（零外部依赖，离线可开）
- 退出码策略：`--fail-on newly_failing|any|never`，可直接当 CI 门禁
**验收数字**：用 good/bad 两组跑出看板，bad 侧被标为退步；HTML 含失败详情；CI 绿。

## v0.4 —— 让"退步"可被量化

- **行为签名**：工具调用序列的最小编辑距离 + 阈值告警（不只 diff，还能判"这次退化有多严重"）
- **真实 agent 适配器矩阵**：至少打通 Claude Code / Codex CLI 的日志导入路径（不要求实时录制，用现有日志即可）
- **不稳定断言识别**：同一条断言在 N 次运行里时红时绿 → 标记为 flaky 并给置信区间
**验收数字**：在 20 次采样的同一任务上，稳定识别出 flaky 断言（与人工判定一致）。

## v0.5 —— 统计上站得住（深化）

- 序贯检验：达到置信度就提前停，不用固定跑 N 次（省钱）
- 样本量规划器：想证明"成功率 ≥ 95%"，告诉你最少要跑多少次
- 失败聚类：把失败 run 按失败签名聚成类别，而不是让人一条条看
**验收数字**：给出"成功率 95% CI"，并证明与重复实验吻合；序贯检验比固定 N 省 ≥30% 运行数。

## v0.6 —— 生态整合

- GitHub Action（别人的 workflow 里一行接入）
- `agenttest init`：给现有仓库生成最小回归骨架
- cassette 查看器（单文件 HTML，可离线看事件流）
- pytest 里直接写 regress 场景
**验收数字**：一个陌生仓库从零接入 ≤5 分钟（README 里给出计时记录）。

## v1.0 —— 成为规范

- `CASSETTE-SPEC 1.0` 冻结（不再加必填字段）+ 版本迁移工具
- CI 里跑**第三方独立实现**做交叉校验（现有 `tools/reference_reader.py` 是起点）
- 至少一个与本项目无关的读取器：证明规范真的可被外人实现
**验收数字**：spec 1.0 + 交叉校验进 CI + 一个外部实现。

## 持续维护（每版都要过的门）

1. 测试全绿 + CI 绿；红 CI 优先于任何新功能
2. CHANGELOG 有本版条目；ROADMAP 勾选更新
3. 运行时零第三方依赖（HTML 报告也不许引 CDN）
4. 不伪造数据：观测不到就写进 `meta.unobserved`
5. 跨平台：Linux CI 绿之外，Windows 上必须能跑（cp936 / BOM / CRLF 三个坑已踩过）

## 不做

- 不做 UI 框架/桌面端
- 不做模型质量评测（那是另一件事）
- 不做云服务/账号体系

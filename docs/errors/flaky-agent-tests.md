# 「agent 的测试时过时不过 / 本地过 CI 不过」

这一页只讲一件事：**在你说「它不稳定」之前，先量化不稳定到什么程度。**

## 为什么不能直接下结论

跑 5 次过 3 次，人会说「它 flaky」。但**3/5 的 95% 置信区间是 0.23–0.88**——
这个区间宽到既容得下「大部分时候能过」，也容得下「大部分时候会挂」。
只凭 5 次就说「这条断言不稳定」，和只凭 5 次就说「它稳定」是同一类错误。

## 先做一件事：量化

```bash
agenttest record --repeat 5 runs/mixed -- python -m my_agent "修复崩溃"
agenttest flaky runs/mixed --assert before:quote_error
```

真实输出：

```text
flaky — 5 次运行，1 条断言
  断言                运行数  通过  通过率  95% CI     判定            备注
  ------------------  ------  ----  ------  ---------  --------------  --------------------------
  before:quote_error  5       3     60%     0.23–0.88  MIXED_OBSERVED  用它判断退步会把噪声当信号
本表 n=5；5 次全过只排除失败率 > 43%，要到 ≤1% 需 381 次
```

三个判定值分别意味着：

| 判定 | 含义 | 你该做什么 |
|---|---|---|
| `PASSED_IN_ALL_RUNS` | n 次全过，**但**区间下界可能远低于你以为的水平 | 看备注里的「只排除失败率 > X%」，别把 n=5 当验证 |
| `MIXED_OBSERVED` | 时过时不过 | 这条断言不能当门禁用，先找不稳定来源 |
| `FAILED_IN_ALL_RUNS` | n 次全挂 | 大概率是真的坏了，不是抖动 |

## MIXED_OBSERVED 的四个常见来源

1. **真正的模型不确定性**：同一 prompt 采样出不同计划 → 断言写得太细（例如断言工具调用顺序），改成断言关键前置条件。
2. **超时**：CI 机器慢，agent 在第 N 步被切断 → 给 `record` 加 `--timeout`，把超时本身当成失败而不是抖动。
3. **环境差异**：本地有缓存/有网/有凭证，CI 没有 → 用 `agenttest import` 把 CI 的日志拉回来，和本地那份 diff。
4. **断言本身写错**：例如断言「引用了 quote_error」，但两次运行的错误文本本来就不同 → 改成断言事件位置（第几个事件之前）。

## 想让它进 CI 门禁

```bash
# 发现不稳定就红（默认 never，只报告）
agenttest flaky runs/mixed --assert before:quote_error --fail-on flaky

# 回归看板里把已知不稳定单独分栏，不让它冒充「退步」
agenttest regress runs/ --assert before:quote_error --flaky-report flaky.json --html
```

## 一句话

**不要问「它稳不稳定」，要问「我这批样本能排除多大的失败率」。**
5 次全过只排除失败率 > 43%；要排除到 1% 需要 381 次——这不是工具的保守，这是数学。
## `agenttest plan` —— 先问代价，再做主张

```bash
$ agenttest plan
样本量规划（跑 n 次全部通过时，能排除多大的失败率）
  目标下界   需要次数   可排除失败率
  0.50       4          > 50%
  0.80       16         > 20%
  0.90       35         > 10%
  0.95       73         > 5%
  0.99       381        > 1%
```

反过来用：你打算说「它很稳定」之前，先看这张表要你跑多少次。
这个命令不引入新算法，它复用 `flaky.runs_needed` 与 `wilson_interval`——
存在的理由是让那个数字**可被查**，而不是埋在某个备注里。
